# Бот публикатор постов в ТГ

Пример ассистента/бота для **контент-завода**: берёт новости из очереди в Google Sheets, помогает подготовить текст поста, сгенерировать изображение и опубликовать материал в Telegram-канал. Проект построен по принципу **детерминированного бэкенда**: вся логика очереди, блокировок строк, статусов и публикации находится в **Google Apps Script**, а ассистент (SMAIPL/LLM) работает как «тонкий адаптер» — принимает сообщения и нажатия кнопок, вызывает API скрипта и отображает строго то, что вернул сервер.

Бот рассчитан на связку с другими ботами контент-завода (например, RSS- или Firecrawl-поиск): они наполняют таблицу, этот бот — **редактирует и публикует** готовые строки.

## Что умеет

- Берёт следующую новость из листа очереди (`ToPublish`) и **блокирует строку** на текущего пользователя.
- Показывает карточку новости с inline-кнопками сценария.
- **Перегенерирует текст** (перефраз в SMAIPL) и сохраняет черновик поста в таблицу.
- **Генерирует изображение** через функцию SMAIPL `openai_gpt_image` (GPT-image-1) по теме поста.
- **Сохраняет URL картинки** и при необходимости **публикует пост в канал** (текст + фото) с отметкой статуса в таблице.
- Поддерживает пропуск новости (снятие лока) и завершение сессии.

### Типовой сценарий (кнопки)

1. **Взять следующую новость** — `get_next_item`
2. **Перегенерировать текст** — `regenerate_text` (+ блок «Черновик поста (перефраз)» от ассистента)
3. **Сохранить черновик новости** — `save_text_draft`
4. **Сгенерировать изображение** — `openai_gpt_image` (SMAIPL)
5. **Перегенерировать изображение** / **Принять изображение и опубликовать пост** — `save_image` с `auto_publish`
6. **Снять лок (пропустить)** — `release_lock`
7. **Завершить** — `finish`

## Архитектура

| Компонент | Файл | Роль |
|-----------|------|------|
| Google Apps Script | `gas_script_publisher.js` | State machine, источник истины: очередь, локи, статусы, запись в Sheets, публикация в Telegram |
| SMAIPL + промпт | `prompt_publisher_v1_stateful_windows.txt` | Строгие правила: на действие пользователя → вызов **302** (`google_run_app_script`) или **364** (`openai_gpt_image`); не менять `message` и кнопки из GAS |

**Контракт ответа GAS:**

```json
{
  "success": true,
  "message": "текст для Telegram",
  "inline_keyboard": [["Подпись кнопки", "command"], ...],
  "data": { "row_id": 123, ... }
}
```

Кнопки в SMAIPL формируются из `inline_keyboard` в формате `##INLINE:[Кнопка1];[Кнопка2]##`.

**Важно:** ассистент **не выбирает строки**, **не придумывает статусы** и **не подтверждает публикацию** без реального ответа GAS. Единственное исключение — блок **«Черновик поста (перефраз)»** после команды `regenerate_text`.

## Структура таблицы

Скрипт ожидает лист очереди (по умолчанию **`ToPublish`**) с колонками:

| Колонка | Поле | Назначение |
|---------|------|------------|
| A–G | createdAt, topic, audience, sourceUrl, summary, rawText, newsId | Базовые поля новости (как у RSS-бота) |
| H | tgTextDraft | Черновик текста поста |
| I | tgTextApproved | Одобренный текст |
| J | imageUrl | URL изображения |
| K | imageApproved | Флаг одобрения картинки |
| L | publishStatus | NEW / IN_PROGRESS / PUBLISHED / ERROR |
| M | publishResultRaw | Сырой результат публикации |
| N–O | lockedBy, lockedAt | Блокировка строки на пользователя |

Опубликованные строки могут переноситься на лист **`PublishedArchive`** (настраивается).

## Быстрый старт

1. **Google Sheets** — таблица с новостями (можно наполнять ботом RSS/Firecrawl из этого репозитория).
2. **Google Apps Script** — создайте проект, вставьте код из `gas_script_publisher.js`, привяжите к таблице.
3. **Script Properties** (рекомендуется):
   - `GOOGLE_SHEET_ID` — ID таблицы
   - `PUBLISH_SHEET_NAME` — имя листа очереди (по умолчанию `ToPublish`)
   - `TELEGRAM_BOT_TOKEN` — токен бота (чтобы не хранить в промпте)
   - `TELEGRAM_CHANNEL_ID` — ID канала (например `-100...`)
4. **Deploy** → Web App (доступ: «Anyone» / выполнение от вашего аккаунта — как принято в вашей среде).
5. **Промпт** — в `prompt_publisher_v1_stateful_windows.txt` замените:
   - все вхождения `<ВАШ_DEPLOYMENT_ID>` на URL вашего Web App;
   - `<ID_КАНАЛА>` и `<BOT_TOKEN>` — на свои значения **или** передавайте их только через Script Properties GAS (см. комментарии в скрипте для `save_image` / `auto_publish`).
6. **SMAIPL** — подключите промпт, убедитесь, что доступны функции:
   - **302** `google_run_app_script`
   - **364** `openai_gpt_image` (для шага генерации картинки)

## Зачем этот пример полезен

- Показывает **второй этап контент-завода**: от сырой новости в таблице до поста в канале.
- LLM не «рулит очередью», а делает **перефраз** и **визуальный prompt** для картинки в рамках жёстких правил.
- Удобная база для доработок: другой формат поста, несколько каналов, модерация, A/B текстов, свои статусы.

## Важно

- Не публикуйте в открытый репозиторий **реальные** `bot_token` и приватные URL с секретами — используйте плейсхолдеры и Script Properties.
- Проект рассчитан на то, что ассистент **не подменяет** ответы GAS. Если модель иногда нарушает правило, критичные действия всё равно выполняются в GAS; логи SMAIPL помогают найти сбой на стороне промпта/платформы.
- Для цепочки «поиск → публикация» используйте вместе с ботами из папок [RSS](https://github.com/EduardBardackiy/SMAIPL/tree/main/%D0%91%D0%BE%D1%82%20%D0%BF%D0%BE%D0%B8%D1%81%D0%BA%D0%B0%20%D0%BD%D0%BE%D0%B2%D0%BE%D1%81%D1%82%D0%B5%D0%B9%20RSS%20%D0%B4%D0%BB%D1%8F%20%D0%BA%D0%BE%D0%BD%D1%82%D0%B5%D0%BD%D1%82-%D0%B7%D0%B0%D0%B2%D0%BE%D0%B4%D0%B0) и [Firecrawl](https://github.com/EduardBardackiy/SMAIPL/tree/main/%D0%91%D0%BE%D1%82%20%D0%BF%D0%BE%D0%B8%D1%81%D0%BA%D0%B0%20%D0%BD%D0%BE%D0%B2%D0%BE%D1%81%D1%82%D0%B5%D0%B9%20%D1%81%20Firecrawl%20%D0%B4%D0%BB%D1%8F%20%D0%BA%D0%BE%D0%BD%D1%82%D0%B5%D0%BD%D1%82-%D0%B7%D0%B0%D0%B2%D0%BE%D0%B4%D0%B0).
