# Бот поиска новостей RSS для контент-завода

Пример ассистента/бота для поиска и сохранения новостей об ИИ, построенный по принципу: **LLM = только интерфейс**, а **вся логика и состояние — в Google Apps Script**.

Бот берёт новости из RSS‑лент (например, через `rss.app`), показывает их по одной с inline‑кнопками и сохраняет подтверждённые новости в Google Sheets.

## Что внутри

- `gas_script_rss.js` — Google Apps Script (Web App): загрузка новостей из RSS, очередь/индексы, сохранение в Google Sheets.
- `prompt_v10_stateful.txt` — промпт для LLM (UI‑слой) с правилами вызова действий Web App и строгим запретом “придумывать” новости.

## Архитектура

Telegram/платформа → LLM (показывает карточки, вызывает действия) → Google Apps Script (логика + состояние) → RSS (источники) → Google Sheets (хранилище).

## Команды (GAS Web App)

- `start_search` — собрать очередь и вернуть первую новость
- `get_next` — перейти к следующей новости
- `confirm_current` — сохранить текущую новость в таблицу
- `finish` — завершить сессию и очистить состояние

## Настройка

1) **RSS‑источники**

В `gas_script_rss.js` задайте RSS‑ленты в массиве `RSS_FEEDS`.

2) **Google Sheets**

В Script Properties (в GAS) задайте:

- `GOOGLE_SHEET_ID` — ID таблицы или ссылка на таблицу (скрипт умеет извлекать ID из URL).

3) **Деплой GAS**

Задеплойте `gas_script_rss.js` как **Web App** и получите URL вида:

`https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec`

4) **Подключение промпта**

В `prompt_v10_stateful.txt` замените `web_app_url` на URL вашего деплоя GAS Web App.

## Почему это устойчиво

- Все тексты новостей и состояние очереди определяет GAS, поэтому LLM не “рулит” логикой.
- LLM обязана вызывать действие (через функцию 302) на каждую кнопку и показывать строго то, что вернул GAS.
